PC WORKFLOWS / REAL TOKEN ACQUISITION

PC Methods.

Every supported computer-assisted route, with a clear boundary between obtaining a genuine token and verifying one.

OFFICIAL META SDK PATHS
THE IMPORTANT LIMIT

A PC can build, deploy, transport and verify. It cannot mint a Quest attestation token.

Meta's current Attestation API is for Android-platform apps running on supported Quest hardware. The actual token request runs inside your authorised native app on the headset; Meta's service signs the result. A PC-only website, Windows process, ADB command or Android emulator is not an alternative token issuer.

Supported ways to request it

TOKEN ISSUED ON QUEST
01 / NATIVE ANDROID

Android Platform SDK · Kotlin

REAL TOKEN PATH

Implement Meta's Device Application Integrity API in your own Android-platform Quest app. The app receives the server nonce, calls DeviceApplicationIntegrity().getIntegrityToken(challengeNonce), then posts the returned token to your backend.

  1. Create/configure your Quest app in Meta's developer dashboard.
  2. Integrate the current Meta Android Platform SDK and initialise it as documented.
  3. Request a fresh nonce from this Studio backend.
  4. Call the API from the running Quest app and send the returned token to your server.

02 / UNITY

Unity · Oculus Platform SDK

REAL TOKEN PATH

Build your Unity project for Android/Quest. Use Oculus.Platform.DeviceApplicationIntegrity.GetIntegrityToken(challengeNonce) from the Quest app and handle the asynchronous request result. The PC is the development/build machine; the call runs on the headset.

  1. Install the Meta/Oculus Platform Unity SDK and configure the app ID.
  2. Set Android as the build target and configure the Quest package/signing setup.
  3. Pass the backend nonce to the SDK call on-device.
  4. POST the returned token to the backend for Meta verification.

03 / UNREAL ENGINE

Unreal · Platform SDK

REAL TOKEN PATH

Build an Android/Quest Unreal app with Meta's Platform SDK integration. Use the documented attestation flow and pass the server-generated challenge nonce to the client API. The Unreal app obtains the token on Quest; your PC builds and deploys it.

  1. Configure the Meta Platform SDK and your app credentials in the project.
  2. Package for a supported Quest Android target.
  3. Call the documented attestation client API with the fresh nonce.
  4. Send the token to your server and verify it with Meta.

04 / NATIVE C / C++

Meta Native Platform SDK

REAL TOKEN PATH

For a native Android Quest application, call ovr_DeviceApplicationIntegrity_GetIntegrityToken(challenge_nonce), check the returned message for errors, and retrieve the token string from the successful response. This is still an on-device app call—not a desktop API.

  1. Integrate the Meta Native Platform SDK in your Android/Quest app.
  2. Generate the nonce on your server and pass it unchanged to the function.
  3. Check the async response with the SDK error/message functions.
  4. Forward the token securely to your backend.

PC-ASSISTED WORKFLOWS

What the computer can do

A / BUILD & DEPLOY

Use PC + USB or wireless ADB

Install Android SDK Platform Tools, enable Developer Mode and Wireless Debugging on the Quest, pair/connect through the ADB Console, then deploy your own signed development build from Android Studio, Unity or Unreal. Launch the app on Quest and let that app request the token.

adb devices -l
adb install -r path/to/your-quest-app.apk
adb shell monkey -p your.own.package.name 1

Replace the package name and APK path with your own app. This installs/launches an app; it does not make ADB itself an attestation client.

B / TOKEN TRANSPORT

Send a Quest-issued token to this Studio

Your own Quest app can POST its returned token directly to your backend. For development, you can also copy the token from your app's authorised debug output and paste it into Meta Attestation → Verify with Meta. Never log production tokens unnecessarily.

Use the exact one-time nonce issued for that verification attempt. A token from another app, package, device, challenge or session will not become valid by copying it across.

C / SERVER VERIFICATION

Verify from the PC backend

The PC can run your Flask backend or another trusted server process and call Meta's /platform_integrity/verify endpoint with the token and that app's server-side App Access Token. Keep credentials in environment variables or a secret manager—never in browser JavaScript, command history, screenshots or Git.

This verifies an existing Meta-issued token. The App Access Token authorises verification; it does not generate or sign attestation tokens.

D / REMOTE DEVELOPMENT

PC build machine, Quest runtime

Unity/Unreal/Android Studio can all run on Windows, macOS or Linux as your development environment. The resulting Android app must execute on supported Quest hardware with network access to Meta's attestation service. Quest Link/PCVR streaming does not move the attestation API onto the PC.

Meta documents Android-platform support and Quest 2, Quest Pro, Quest 3 and Quest 3S device support. Confirm current requirements before shipping.

NOT REAL TOKEN-GENERATION METHODS

These do not produce a genuine Meta token

Website / browser JavaScript
Cannot call the native Quest attestation API.

Windows / macOS / Linux executable alone
No documented desktop token-issuance API.

ADB shell or serial number
Can inspect/connect; cannot mint Meta signatures.

Android emulator
Not a supported Quest hardware attestation environment.

Quest Link / PCVR
Streams PC content; does not make the PC a Quest attestation client.

Hand-built JWT / copied token
Cannot create a valid Meta signature or satisfy a fresh nonce.

META FLOW

How genuine attestation works

  1. Backend generates a unique Base64URL nonce (22–172 chars).
  2. Your native Quest app calls getIntegrityToken(challengeNonce).
  3. Meta signs the token; your app sends it to your backend.
  4. Backend calls Meta's /platform_integrity/verify endpoint.
  5. Backend validates nonce, timestamps, package, signing digest and device state.

ADB NETWORK MODEL

Why a local companion?

Render is a cloud server and cannot discover devices on your home Wi-Fi. Android Debug Bridge must execute on a computer with Android Platform Tools installed and network access to the Quest.

Run python adb_agent.py on that computer. Protect it with a strong ADB_AGENT_TOKEN; do not expose the companion publicly without a secure tunnel and origin restrictions.

The companion exposes only device listing, wireless pair/connect/disconnect and basic read-only device information. It does not root the headset or access another app's private data.
